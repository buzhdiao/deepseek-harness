# 08 · 安全须知（SAFETY.md）与 developer preview 边界

**Developer preview 是什么意思。** README.md:11-15：项目处于 developer preview，快速迭代，**会有破坏兼容性的变更**；公共 API 都是 pre-stable（AGENTS.md:7）。工程上的配套措施是：持久化类型变更要显式声明并逐消费者更新；已发布 Session 数据只增代不删改（相邻迁移加版本化后继，绝不移动/覆写/删除已提交世代，AGENTS.md:7）；每个外部可感知的破坏性变更立即记入升级指南。文档型仓库更是把「诚实标注」做进机制：`packages/experimental/` 的能力「无产品支持承诺」（AGENTS.md:68），实验 API 的调用方位置由脚本门禁限制。

**SAFETY.md 的四段警示**（SAFETY.md:5-27）：

1. **实验状态**（:5-9）：未经安全审计，不得当作安全或生产就绪。项目能执行模型生成的代码与命令、加载第三方插件、访问网络/进程/凭据/文件——错误模型输出、缺陷、误配置、恶意输入或不可信插件都可能损害宿主机、改删文件、泄露数据。
2. **沙箱局限**（:11-15）：沙箱、审批提示、权限控制能降低风险但不保证隔离；即使正确执行的限制也保护不了「本就允许项目访问的资源」。不要把它当不可信工作负载的唯一安全控制。
3. **负责任使用**（:17-23）：最小权限运行；优先一次性虚拟机/容器/专用环境；对可访问文件保留备份；不接受风险就不要暴露敏感凭据；放行前审查插件、配置与待执行命令。
4. **无担保**（:25-27）：MIT 许可、风险自担。

**代码层的对应机制。** 警示不是贴在文档里的，而是有实现承接：进程限制走 `ctx.sandbox` 后端（消费者在 spawn 前包装 argv，docs/architecture.md:159）；工具执行前有 `tools/pre-execute` 审批瀑布（见 06 篇）；配置在加载点 fail loud（AGENTS.md:145「误配置大声失败，绝不静默跳过缺失的引用物」）；信任边界收窄到解析器/配置、队列、模型/工具 JSON、持久文件、worker、进程与线路边界（AGENTS.md:147「类型化的同进程边界信任 TypeScript」）——这既减少运行时校验，也把真正需要校验的地方写明在案。

**给读者的建议。** 学习与二开时：默认用一次性环境；不要把真实凭据放进 `.env` 之外的任何地方（真 API 测试读 `DEEPSEEK_API_KEY` 与根 `.env`，CI 无 key 自动跳过，AGENTS.md:128）；审阅第三方插件的 `cordis.yml` 与入口代码——插件享有与内置插件同等的进程权限，「一切皆插件」的能力面同时也是攻击面。
