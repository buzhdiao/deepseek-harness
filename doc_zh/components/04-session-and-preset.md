# 04 · Session 与 preset 体系

**Session：事件溯源的会话。** `Session`（packages/core/session/src/index.ts:631）是一份只追加事件日志，事件词汇表 `SessionEventMap`（types.ts:364）通过声明合并向插件开放。核心不变量有三条：`seq = log.length`（序号连续，index.ts:841 的 `get seq`）；「Model-visible ⟺ logged」（AGENTS.md:138——每个进入模型请求的输入必须能从日志重建）；事件载荷必须无损 JSON（`append`（index.ts:962）先用 `snapshotJsonValue` 做一次快照式校验，BigInt/函数/循环引用等在追加点就失败，而不是等后端 flush 才炸）。`turn/start…turn/end`、`step/start…step/end`、`user/message`、`assistant/message`（内嵌压缩定时流 + token 账目）、`tool/call`/`tool/result` 是持久事实；`request/header`（带 initial/resume/change/series 四种 reason）只用于重建请求头。

**派生历史与表面。** 模型看到的消息不是直接存的，而是从日志的「有序表面」推导：每个消息型事件带 `surfaceOp`（append 或 replace），`deriveMessages()`（index.ts:1190）沿表面走，压缩（compaction）的 replace 会把被遮蔽节点从推导中删掉；结果按 `contentGeneration` 缓存，纯尾部增长 O(新节点)。商店 `SessionStore`（index.ts:1265）是 Cordis 服务：`create`/`prepare`+`enter`+`announce` 两套创建路径（后者让 agent 工厂能把会话与循环折叠进同一个有序 effect，保证拆除顺序），`session/created`/`disposed`/`event`/`flush` 四个事件是持久化插件的全部接口（flush 是被 await 的并行检查点，index.ts:1598）。fork 时开着的回合会被合成收尾（`buildForkSeed`），格式版本 `SESSION_FORMAT_VERSION = 4`（types.ts:108）单调整数，迁移由每个 `session-format-vN-to-vN+1` 包负责一步。

**Preset：可热换的能力组合。** `AgentPresetRegistry`（packages/preset/agent-preset-registry/src/index.ts:71）管理「preset id → 插件行列表」：`register()` 立即激活；激活 = `createScope`（dsh-scope，scope/src/index.ts:174）铸造隔离作用域 + `mountPreset`（mount.ts:250）装载整棵插件子树 + 泄漏审计（服务必须住在 isolate realm，否则拒绝挂载）。每次成功挂载是一个 **Generation（代）**：引用计数 + 退役标记，新代就位后旧代等最后一个 agent 离开才销毁——修订保持语义。agent 通过 `mount()`/`select()` 绑定到某个代（作用域键经 `bindScopeParent` 挂到代键上，事件沿作用域链向上流动，见 scope/src/index.ts:218 `scopeTarget`）；`select` 只允许在首个回合前，并把选择写进会话日志（`agent-preset/selected` 事件）。preset 的组合是插件行（如 persona 行、`isolate` realm 内的工具行），这正是 architecture.md:150「Give one session a different capability set → compose an agent preset」的实现。
